# Грава — Mini App для @grava_ai_bot

Главное место, где делают заказы: лазерные чертежи, 3D-фигурки, детали по размерам и скан по фото.
Плюс «Мои работы», 3D-просмотр, редактор, конструктор деталей, сборщик шарниров и покупка кредитов.
Обычная статичная страница: без сборщиков и npm, работает на GitHub Pages.

| `create.js` | вкладка «Создать» — как переписка: лента открытого проекта (его работы и активные заказы: облачко запроса справа, карточка результата слева с кнопками следующего шага, карточка ожидания с этапом) и композер внизу (поле до 6 строк, скрепка для фото, режимы Лазер / 3D / Подвижная / Деталь / Скан, цена у кнопки отправки, изменение описанием из карточки, черновик из чата). «Подвижная» не запоминается: последним режимом сохраняется «3D», после отправки подвижной следующий заказ снова обычный; пока выбрана подвижная — кнопка «Создать подвижную» и строка «Подвижная на шарнирах — тело будет из звеньев · Сделать обычной»; если в тексте «обычный», «цельный», «неподвижный», «статуэтка» и т. п. (кроме «подвижный только хвост») — сам переключает на «3D» с тостом. Плюс экраны заказа для правки с экрана работы. Фото — поворот по EXIF, до 1600 px, JPEG 0.85 |
| `projects.js` | проекты: каждая новая работа — свой проект, как отдельный чат. Список собирается из `?a=me` (работы группируются по `project`) и активных заказов; работы без проекта — в «Ранее». Боковая панель по кнопке в шапке «Создать», шапка с названием проекта, выбор проекта при запуске |
| `ask.js` | уточняющие вопросы перед новым заказом по тексту: «Думаю…», карточка «Уточню пару деталей» с вариантами, «Свой вариант», «Пропустить», ответ из композера, свёрнутая строка ответов |
| `jobs.js` | заказы: цены из `?a=me`, отправка, опрос статуса раз в 3 секунды, экран ожидания с этапами по таймеру, карточки ожидания в ленте, тост «✅ Готово». Активные заказы лежат в `localStorage` — после перезапуска опрос продолжается |
| `editor.js` | вкладка «Редактор»: рисование, обводка для ИИ, обрезка, отправка правки |
| `cad.js` | конструктор деталей по размерам: параметры, превью, отправка файла, починка |
| `cad-worker.js` | фоновый поток конструктора: считает деталь движком OpenSCAD |
| `flexi.js` | экран «Шарниры». Человек ничего не тапает: приложение само ставит шарниры в лучших местах (точки автопоиска → проверка каждой → красные убираются, их причины запоминаются), само собирает и сразу показывает, как фигурка шевелится. Пока идёт автосборка — шаги «Ищу, где фигурка должна гнуться…», «Проверяю шарниры… (3 из 8)», «Собираю…»; нижняя кнопка скрыта, «Назад» всё отменяет. Результат: большое превью с шевелением, строка «Поставил 9 шарниров: шея, 4 лапы, хвост — 4 звена. Гнётся до ±80°», жёлтый блок «Где не получилось» с причиной и советом, «Сохранить подвижную модель», «Изменить шарниры», «Размер», «Как печатать». Хороших мест нет — «Не получилось поставить шарниры» с причиной и кнопками «Сделать крупнее» (+40 мм) и «Поставить вручную». Ручной редактор (по «Изменить шарниры»): тап — шарнир, тап по шарниру — «Убрать», «Поставить автоматически», «Тонкая настройка», «Готово» (красные пропускаются). `flexiExplain(why, place)` переводит причины ядра в понятные («Кончик хвоста: слишком тонкое для шарнира» — «Сделай фигурку крупнее — от 18 см»); место — «Шея», «Тело», «Лапа 1…4», «Хвост», «Кончик хвоста». Где кнопка: у модели из режима «Подвижная на шарнирах» (`flexi: true`) — главная «Сделать подвижной · бесплатно» на экране работы и в ленте проекта, у остальных 3D-моделей (кроме уже собранных на шарнирах и деталей) — «Попробовать на шарнирах» |
| `flexi-worker.js`, `flexi-core.js` | сборщик шарниров: модель перепаивается (воксели → levelSet); позвоночник (от морды через тело до кончика хвоста) и лапы режутся на звенья «ушко в петле» по образцу брелока-крокодила «sleep croc» (сустав на всё звено: плоская стойка-стадион поперёк тела проходит сквозь толстую пластину-ушко, срощенную с телом; дырка ушка — стадион, прокрученный на ±(α + 3°) и раздутый на зазор; петля почти во всю высоту, люфт 0.6 мм сверху и снизу); лапы держатся на своих звеньях позвоночника. `placeCut` — разрез по тапу, `checkCut` — проверка одного разреза на целой модели (вместе с соседним разрезом ближе к телу на той же цепочке): сустав внутри тела с запасом от кожи, держит в 6 сторон, поворачивается на ±α, ничего не отрезал, звено не висит над столом (низ выше 0.2 мм). `autoCuts` — только предложения. Размеры сустава — в долях звена с невысоким минимумом (W — ширина, S = min(W, H)): стойка 0.24·W × 0.14·W (от 1.8 × 1.2), стенка ушка 0.20·W (от 1.6), перекладины 0.20·S (от 1.2), пластина ушка — что осталось по высоте; влезает в звено шириной от ~9 мм; при смене длины суставы пересчитываются. Петля и кольцо сустава лежат в коже, сжатой на 0.8 мм (skinIn; допуск 1 мм³, щель разреза ±1.5 мм не считается); шейка ушка не проверяется — она обрезается по коже. skinIn строится по вокселям: прорези и полости уже 2.4 мм заплавлены (у готовой подвижной модели — эублефара от бота — сустав в них виден, но наружу не торчит), под столом кожа продлена на 2 мм и после сжатия отрезана по z = 0 — снизу у стола не сжимается. Низ и верх сустава — по полю skinIn в каждой точке следа петли; размер сустава — от min(2w, высота тела, свободная высота над следом). Если на хвосте < 3 предложенных звеньев или у лапы нет суставов — подсказка «сделай крупнее». Тест сустава — бруски 16×11, 12×10, 9×8 (зазор ≥ 0.4, держит в 6 сторон, ±20° без касания, толщины по готовой сетке) и 7×6 (не влезает). Автопроверка (manifold-3d) |
| `tests/flexi.test.mjs` | проверка сборщика: разрезы рукой на ящерице с сужающимся хвостом (тап посередине хвоста — зелёный, 2 детали; у кончика — красный с причиной), кот, осьминог, змея, ящерица, скелет и настоящий эублефар `tests/gecko.stl` (бороздки притягивают разрез): «✨ Предложить» → тап по точкам → проверка → сборка; размер 15 см — ящерица (шея, тело, 2 звена хвоста зелёные), эублефар (шея, тело, 2 звена хвоста), скелет (шея и тело зелёные, хвост-стержень — красная причина в цифрах); бруски 16×11, 12×10, 9×8 — со сжатой кожей; все модели — на 15 см; у всех — «ничего не выходит за кожу» и «сустав внутри skinIn» — `node tests/flexi.test.mjs`, STL в `tests/out/` |

## Публикация

1. GitHub → репозиторий → **Settings → Pages**.
2. **Source:** Deploy from a branch → **main** → **/ (root)** → Save.
3. Через 1–2 минуты страница будет тут: https://mofv231008-commits.github.io/grava-app/

Если открыть ссылку в обычном браузере, будет надпись «Открой приложение из бота @grava_ai_bot». Так и задумано: пока приложение работает только внутри Telegram. Но код уже готов к сайту — всё про Telegram в `tg.js`, все запросы в `api.js`.

## Проверка без сервера

`…/grava-app/?mock=1` — приложение открывается и в обычном браузере, сервер не нужен: `createJob` сразу отдаёт номер, `jobStatus` на третий опрос отвечает «готово» с работой нужного вида. В тексте заказа «ошибка» — ответит ошибкой, «кредит» — «не хватает кредитов», «вопрос» — вопросом бота. `&draft=1` — черновик из чата с текстом и 2 фото; `&mockphotos=0` (или 1, 3…) — другое число фото.
`clarify` для текста короче 15 символов отвечает примером про змею (2 вопроса), для длинного — «уже понятно» (`ready: true`).
Новый заказ без `project` получает новый проект; старые работы-примеры лежат в «Ранее», ещё один пример — проект «Ключница».
Сборщик шарниров: `?mock=1&flexi=o14` — ящерица, шарниры встают сами; `&flexi=o15` — плоская ящерица, ни один шарнир не помещается
(экран «Не получилось»); `&flexi=o4` — модель не в режиме «Подвижная на шарнирах» (предупреждение о позе). Модели строятся тут же, по карте высот.

## Как обновлять

Меняешь файлы в ветке `main`, GitHub Pages обновится сам за пару минут.
Если Telegram показывает старую версию, увеличь число в `?v=…` у файлов в `index.html`.

Обычно приложение открывается на вкладке «✨ Создать». Ссылка `https://mofv231008-commits.github.io/grava-app/#editor` сразу открывает вкладку «Редактор»,
`https://mofv231008-commits.github.io/grava-app/?cad=<номер>` — конструктор детали,
`https://mofv231008-commits.github.io/grava-app/?flexi=<номер>` — сборщик шарниров,
`https://mofv231008-commits.github.io/grava-app/?draft=1` — «Создать» с черновиком из чата (кнопка бота «🚀 Открыть и продолжить»).

## Бот молчит — всё в приложении

Пока человек работает в приложении, бот ничего не пишет в Telegram: ни статусов, ни эскизов, ни файлов. Готовая работа сохраняется в «Мои работы»
(«Можно закрыть приложение — работа сохранится в «Мои работы»»). В чат работа попадает только по кнопке «Отправить в Telegram» (`Api.send(id)`, `?a=send`):
она есть на экране любой готовой работы — у эскиза вторичной кнопкой (бот пришлёт картинку), у модели, чертежа, детали и подвижной модели — главной.
Тост — «Отправлено в Telegram ✓» или «Не получилось отправить, попробуй ещё раз».

- Редактор: «Изменить по описанию» и «Сохранить как есть» отправляют `project` (проект работы или открытый на «Создать»). В ответе `id` нового эскиза —
  редактор закрывается и открывается этот эскиз с обычными кнопками следующего шага. У правки чертежа `id: null` — «Сохранено в «Мои работы»».
- Конструктор детали и сборщик шарниров: «Сохранить STL/DXF» → `{ ok, id }` — новая работа в том же проекте. Под превью — «Сохранено в «Мои работы»»
  и кнопки «Открыть работу» и «Отправить в Telegram».

## Черновик из чата

Бот больше не принимает заказы: текст и фото из чата он сохраняет черновиком (`?a=chatdraft`, фото — `?a=chatdraft&id=<номер>`).
При старте и при каждом открытии «Создать» приложение спрашивает черновик и, если композер пуст, подставляет в него текст и фото
(над полем плашка «Из сообщения боту ×»). Режим — по фото: 2+ фото → скан, одно → 3D, только текст → последний выбранный.
Когда заказ создан или нажато «×», время черновика (`at`) запоминается в `localStorage['grava.draftUsed']` — больше он не подставится.

## Проекты

Каждая новая работа живёт в своём проекте: свой запрос, свои эскизы, модели и правки. Проекты собираются на фронте:
работы из `?a=me` группируются по полю `project` (у старых работ оно пустое — они в «Ранее», внизу списка),
активные заказы из `localStorage` — в своём проекте. Название — `prompt` первой работы (до ~40 символов), если пусто — её `title`.

- «+ Новый проект» — пустая лента с примерами. Первый `createJob` уходит без `project`, сервер заводит проект и возвращает его — он становится текущим.
- Все следующие заказы с этого экрана — с `project`. Правка, 3D из эскиза, размер — в проект исходной работы.
- Текущий проект — `localStorage['grava.project']`. При запуске открывается он, если в нём были работы за последние сутки, иначе — новый проект.
- Черновик из Telegram (`?draft=1`) всегда открывается в новом проекте. В «Моих работах» у карточки — строчка с названием проекта, тап открывает проект.

## Уточняющие вопросы

Новый заказ по тексту в режимах Лазер, 3D, Подвижная, Деталь сначала уходит в `Api.clarify` (POST `grava-app-job`, `kind: "clarify"`, бесплатно, ждём до 15 секунд).
Пока ждём — облачко с текстом и «Думаю…». Вопросов нет, ошибка или 15 секунд без ответа — сразу обычный заказ.
Есть вопросы — карточка «Уточню пару деталей»: варианты-чипсы, последний — «Свой вариант» (поле ввода), «Создать» с ценой и «Пропустить».
Итоговый текст — исходный плюс ответы: `змея. Какая змея?: Кобра. Стиль?: Мультяшный`. Текст, напечатанный в композер, пока висят вопросы, —
«Свой вариант» сразу для всех вопросов. Правки, 3D из эскиза, скан, заказы с фото и запросы, по которым уже спрашивали (`localStorage['grava.asked']`), — без вопросов.

## Оформление

Цвета — переменные в `style.css` (`--bg`, `--surface`, `--surface-2`, `--border`, `--text`, `--text-2`, `--accent`…), тёмная тема — `[data-theme="dark"]`.
Тексты — простые, на «ты», без жаргона: «Сделать 3D-модель», «Изменить», «Отправить в Telegram», цены словами («1 кредит», «5 кредитов»).
Акцент (терракотовый) — только у одной главной кнопки на экране, логотипа «Г» и активной вкладки. Для акцентного мелкого текста на светлом фоне
есть `--accent-text` (чуть темнее, чтобы контраст был не ниже 4.5:1). Иконки — тонкие линейные из спрайта в `index.html`.
