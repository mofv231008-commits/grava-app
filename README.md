# Грава — Mini App для @grava_ai_bot

Главное место, где делают заказы: лазерные чертежи, 3D-фигурки, детали по размерам и скан по фото.
Плюс «Мои работы», 3D-просмотр, редактор, конструктор деталей, сборщик шарниров и покупка кредитов.
Обычная статичная страница: без сборщиков и npm, работает на GitHub Pages.

## Файлы

| Файл | Что внутри |
|---|---|
| `index.html` | разметка всех экранов и спрайт линейных иконок (`<svg class="i"><use href="#i-…"/></svg>`) |
| `style.css` | оформление: тёплый фон, заголовки с засечками, один терракотовый акцент. Все цвета — переменные в `:root` и `[data-theme="dark"]` |
| `fonts/` | Source Serif 4 (500, 600; кириллица и латиница, woff2) для заголовков — лежит здесь, из сети не грузится. Лицензия — `fonts/OFL.txt` |
| `tg.js` | всё, что зависит от Telegram: тема (по `colorScheme`, вне Telegram — по `prefers-color-scheme`), цвет шапки/фона/нижней полосы, высота видимой области под клавиатуру, MainButton, BackButton, вибрация, окошки, оплата, свайпы. Вне Telegram — запасные варианты: своя кнопка внизу, «‹ Назад» и `history.back()`, `alert`/`confirm` |
| `api.js` | все запросы к серверу — других мест нет: `Api.me()`, `createJob(data)`, `jobStatus(id)`, `fileUrl(id, what)`, `send(id)`, `buy(pack)` (+ файлы, редактор, конструктор). Авторизацию добавляет одна функция `authParams()` — сейчас initData, потом токен сайта. `?mock=1` — сервер-понарошку |
| `app.js` | вкладки, «Мои работы», экран работы (один и для готового результата, и для работы из списка: «Лепим 3D-модель», другой размер, правка словами, другой формат…), баланс и оплата, 3D-просмотр, запуск |
| `create.js` | вкладка «Создать» — как переписка: лента (последние 10 работ и активные заказы: облачко запроса справа, карточка результата слева с кнопками следующего шага, карточка ожидания с этапом) и композер внизу (поле до 6 строк, скрепка для фото, режимы Лазер / 3D / Подвижная / Деталь / Скан, цена у кнопки отправки, правка словами из карточки, черновик из чата). Плюс экраны заказа для правки с экрана работы. Фото — поворот по EXIF, до 1600 px, JPEG 0.85 |
| `jobs.js` | заказы: цены из `?a=me`, отправка, опрос статуса раз в 3 секунды, экран ожидания с этапами по таймеру, плашки «⏳ Леплю…» на главной, тост «✅ Готово». Активные заказы лежат в `localStorage` — после перезапуска опрос продолжается |
| `editor.js` | вкладка «Редактор»: рисование, обводка для ИИ, обрезка, отправка правки |
| `cad.js` | конструктор деталей по размерам: параметры, превью, отправка файла, починка |
| `cad-worker.js` | фоновый поток конструктора: считает деталь движком OpenSCAD |
| `flexi.js` | экран «🦴 Шарниры» (режим «⛓ Цепочка»): модель открывается целиком, разрезы ставит человек — тап по фигурке (поперёк ветви в ближайшей точке скелета, к бороздке ближе 3 мм притягивается), тянуть — вдоль позвоночника, тап по разрезу — «Убрать», «↺ Сбросить»; «✨ Предложить» показывает точки автопоиска (тап по точке — разрез). Каждый разрез сразу проверяется: зелёный — сустав получится, красный — с причиной в цифрах («тут тонко: высота 7.8 мм, нужно от 9.3 — …», «сустав вылезает наружу сбоку на 4.6 мм³»); кружки суставов ближе 2 мм — «слишком близко». «Собрать STL» — когда все разрезы зелёные. Вверху — «Размер: 15 см». Превью, отправка |
| `flexi-worker.js`, `flexi-core.js` | сборщик шарниров: модель перепаивается (воксели → levelSet); позвоночник (от морды через тело до кончика хвоста) и лапы режутся на звенья «ушко в петле» по образцу брелока-крокодила «sleep croc» (сустав на всё звено: плоская стойка-стадион поперёк тела проходит сквозь толстую пластину-ушко, срощенную с телом; дырка ушка — стадион, прокрученный на ±(α + 3°) и раздутый на зазор; петля почти во всю высоту, люфт 0.6 мм сверху и снизу); лапы держатся на своих звеньях позвоночника. `placeCut` — разрез по тапу, `checkCut` — проверка одного разреза на целой модели (вместе с соседним разрезом ближе к телу на той же цепочке): сустав внутри тела с запасом от кожи, держит в 6 сторон, поворачивается на ±α, ничего не отрезал, звено не висит над столом (низ выше 0.2 мм). `autoCuts` — только предложения. Размеры сустава — в долях звена с невысоким минимумом (W — ширина, S = min(W, H)): стойка 0.24·W × 0.14·W (от 1.8 × 1.2), стенка ушка 0.20·W (от 1.6), перекладины 0.20·S (от 1.2), пластина ушка — что осталось по высоте; влезает в звено шириной от ~9 мм; при смене длины суставы пересчитываются. Петля и кольцо сустава лежат в коже, сжатой на 0.8 мм (skinIn; допуск 1 мм³, щель разреза ±1.5 мм не считается); шейка ушка не проверяется — она обрезается по коже. skinIn строится по вокселям: прорези и полости уже 2.4 мм заплавлены (у готовой подвижной модели — эублефара от бота — сустав в них виден, но наружу не торчит), под столом кожа продлена на 2 мм и после сжатия отрезана по z = 0 — снизу у стола не сжимается. Низ и верх сустава — по полю skinIn в каждой точке следа петли; размер сустава — от min(2w, высота тела, свободная высота над следом). Если на хвосте < 3 предложенных звеньев или у лапы нет суставов — подсказка «сделай крупнее». Тест сустава — бруски 16×11, 12×10, 9×8 (зазор ≥ 0.4, держит в 6 сторон, ±20° без касания, толщины по готовой сетке) и 7×6 (не влезает). Автопроверка (manifold-3d) |
| `tests/flexi.test.mjs` | проверка сборщика: разрезы рукой на ящерице с сужающимся хвостом (тап посередине хвоста — зелёный, 2 детали; у кончика — красный с причиной), кот, осьминог, змея, ящерица, скелет и настоящий эублефар `tests/gecko.stl` (бороздки притягивают разрез): «✨ Предложить» → тап по точкам → проверка → сборка; размер 15 см — ящерица (шея, тело, 2 звена хвоста зелёные), эублефар (шея, тело, 2 звена хвоста), скелет (шея и тело зелёные, хвост-стержень — красная причина в цифрах); бруски 16×11, 12×10, 9×8 — со сжатой кожей; все модели — на 15 см; у всех — «ничего не выходит за кожу» и «сустав внутри skinIn» — `node tests/flexi.test.mjs`, STL в `tests/out/` |

## Публикация

1. GitHub → репозиторий → **Settings → Pages**.
2. **Source:** Deploy from a branch → **main** → **/ (root)** → Save.
3. Через 1–2 минуты страница будет тут: https://mofv231008-commits.github.io/grava-app/

Если открыть ссылку в обычном браузере, будет надпись «Открой приложение из бота @grava_ai_bot». Так и задумано: пока приложение работает только внутри Telegram. Но код уже готов к сайту — всё про Telegram в `tg.js`, все запросы в `api.js`.

## Проверка без сервера

`…/grava-app/?mock=1` — приложение открывается и в обычном браузере, сервер не нужен: `createJob` сразу отдаёт номер, `jobStatus` на третий опрос отвечает «готово» с работой нужного вида. В тексте заказа «ошибка» — ответит ошибкой, «кредит» — «не хватает кредитов», «вопрос» — вопросом бота. `&draft=1` — черновик из чата с текстом и 2 фото; `&mockphotos=0` (или 1, 3…) — другое число фото.

## Как обновлять

Меняешь файлы в ветке `main`, GitHub Pages обновится сам за пару минут.
Если Telegram показывает старую версию, увеличь число в `?v=…` у файлов в `index.html`.

Обычно приложение открывается на вкладке «✨ Создать». Ссылка `https://mofv231008-commits.github.io/grava-app/#editor` сразу открывает вкладку «Редактор»,
`https://mofv231008-commits.github.io/grava-app/?cad=<номер>` — конструктор детали,
`https://mofv231008-commits.github.io/grava-app/?flexi=<номер>` — сборщик шарниров,
`https://mofv231008-commits.github.io/grava-app/?draft=1` — «Создать» с черновиком из чата (кнопка бота «🚀 Открыть и продолжить»).

## Черновик из чата

Бот больше не принимает заказы: текст и фото из чата он сохраняет черновиком (`?a=chatdraft`, фото — `?a=chatdraft&id=<номер>`).
При старте и при каждом открытии «Создать» приложение спрашивает черновик и, если композер пуст, подставляет в него текст и фото
(над полем плашка «Из чата ×»). Режим — по фото: 2+ фото → скан, одно → 3D, только текст → последний выбранный.
Когда заказ создан или нажато «×», время черновика (`at`) запоминается в `localStorage['grava.draftUsed']` — больше он не подставится.

## Оформление

Цвета — переменные в `style.css` (`--bg`, `--surface`, `--surface-2`, `--border`, `--text`, `--text-2`, `--accent`…), тёмная тема — `[data-theme="dark"]`.
Акцент (терракотовый) — только у одной главной кнопки на экране, логотипа «Г» и активной вкладки. Для акцентного мелкого текста на светлом фоне
есть `--accent-text` (чуть темнее, чтобы контраст был не ниже 4.5:1). Иконки — тонкие линейные из спрайта в `index.html`.
